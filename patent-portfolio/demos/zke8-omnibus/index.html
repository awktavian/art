The E8 Omnibus: two lattice techniques, rendered as demoscene

The estate already generates an eight-dimensional carrier field and quantizes it with the residual E8 lattice vector quantizer, then labels each vector by one of the 240 roots of the lattice. Those two mechanisms are the whole show here: ported to browser GLSL and JavaScript, with no new dependencies, and with every frame reproducible from a URL.

Nothing in the estate compiles to a shader — the JIT legs produce a dylib and a wasm32 module, and the shader machinery is a parser, not a generator. So the port is honest transcription: the shader computes the same formula as the CPU reference, the two paths are measured against each other in the browser, and the reference bytes are what a SHA-256 pin describes.

Two techniques

  • 1 · Residual ladder

    Nested E8 Voronoi cells, each level sqrt(240) ≈ 15.492× finer than the last. Hue is the lattice's own f2_8 quotient (1 zero class, 120 root classes, 135 singular classes); brightness is depth inside the cell against the covering radius sqrt(2); the gold filament traces the neighbourhood of the exact-boundary set that the estate's conservative CPU kernel refuses.

    Open the ladder

  • 2 · Root shell

    The 240 roots as a direction code, indexed by an analytic closed form (one 8-lane pass plus 28 integer candidates, instead of 240 dot products) that is proven equal to the estate's 240-row table. Hue is the root index 0..239; gold is where the (±1,±1,0⁶) and (±½)⁸ families tie; ice is a Weyl chamber wall.

Same seed, same pixels

The claim. A URL carries the seed and the frame number; the CPU reference renders them with operations ECMA-262 specifies exactly — a triangle-wave carrier instead of Math.sin (which the standard leaves implementation-approximated), and a frozen float32 scale table built by multiplication instead of Math.pow. The digest below is SHA-256 over the raw RGBA bytes of a 128×128 canonical frame, so it is a property of the seed, not of the machine.

The disclosure. The CPU reference is canonical and is what the pin describes. The live canvas is WebGL2 and therefore float32 end to end; both demos measure the per-byte GPU-vs-reference delta at load and print it, per device, rather than claiming the two are bit-identical. The estate's own E8 decoder certificate is EXPIRED (2026-10-01) and its codec docstring claims no IEEE-level bit identity — this port inherits that honesty.

Determinism pins — node tools/determinism-harness.mjs --check tools/pin.json compares these against a render from a fresh process. The two hub previews above run the house law; the rows below pin both laws, which is why the same seed and frame appear twice with different digests.

Controls, both pages

Seed · frame · ladder depth · residual threshold · filament radius · carrier amplitude. Each control rewrites the hash, so Copy URL is the reproduction recipe. The frame slider and Play drive the animation; prefers-reduced-motion: reduce starts every page paused on the pinned frame. The readout under the canvas is an aria-live region carrying the measured numbers in text.

One honest caveat about the depth slider. The estate's quantizer stops as soon as the residual converges (‖r‖² < threshold²·8), so asking for more levels than the vector needs does nothing — the harness proves the knob is wired by testing at threshold = 0, where every requested level is emitted and the digest changes. A slider that the shipped config can override is disclosed, not hidden.
